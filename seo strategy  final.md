## STEP 2 — KEYWORD STRATEGY (Do This Before Creating Any Page)

### 2.1 How to Build Your Keyword List

Collect 50+ keywords in these 5 categories:

**Category A — Commercial (Primary money keywords)**
Format: "best [niche] in [location]", "[location] [niche] contact number"

**Category B — Hindi/Regional Variants (High-value, low competition)**
Format: "[location] mandir [niche]", "[location] mandir ke sabse bade [niche]"
These are almost NEVER targeted by competitors — instant ranking opportunity.

**Category C — Informational (Attracts research-phase visitors)**
Format: "what is [topic]", "[location] famous for", "[location] history"

**Category D — Contact/Transactional (Highest buying intent)**
Format: "[location] [niche] contact number", "[niche] whatsapp number"

**Category E — Competitor/Comparison (People comparing)**
Format: "best [niche] reviews", "top [niche] in [location]"

### 2.2 Keyword Assignment Rule — ONE Page Owns Each Cluster
Do NOT put all keywords on one page. Each page owns a cluster:

| Page | Primary Keyword | Cluster Focus |
|---|---|---|
| index.html | best [niche] in [location1] | Brand + all locations briefly |
| best-[niche]-[location2].html | best [niche] in [location2] | Location2 commercial |
| [niche]-[city].html | [niche] in [city] | City-specific |
| [service1]-[location].html | [service1] in [location] | Service 1 |
| [service2]-[location].html | [service2] in [location] | Service 2 |
| contact.html | [location] [niche] contact number | All contact keywords |
| history-of-[location].html | [location] is famous for | Informational |
| about-[sacred-place].html | about [sacred place] | Place informational |
| real-[niche]-[state].html | how to find real [niche] | Buying guide |

### 2.3 Keyword Relevance Filter — CRITICAL
Before adding any keyword, ask: "Does this keyword describe where we actually operate?"

**SKIP these types — they HURT rankings:**
- Keywords for cities you don't serve (e.g., competitor's city)
- Tourism keywords (resorts, places to visit) — off-topic dilutes authority
- Competitor personal names — legally and algorithmically risky

**KEEP everything else** — even unusual keyword orders ("mayong best tantrik" AND "best mayong tantrik" — both must be present as they represent different search patterns).

## STEP 4 — FAVICON SETUP (Google Search vs Browser Tab)

### Why Favicon Doesn't Show in Google Search (Most Common Mistake)
Browser tab favicon = any size works, even 2MB file
Google Search favicon = strict rules:
- File must be **under 100KB** (Google has a soft download limit)
- Must be **minimum 48x48 pixels** (Google ignores smaller)
- Recommended size: **192x192 pixels** (what Google actually displays)
- Must use **root-relative paths** (`/favicon.ico`, NOT `./favicon.ico`)
- Must have a **`sizes` attribute** in the link tag

### Correct Favicon Link Tags (Add to ALL pages)
```html
<link rel="icon" href="/favicon.ico" sizes="any">
<link rel="icon" type="image/png" href="/favicon.png" sizes="48x48">
<link rel="icon" type="image/png" href="/favicon-192.png" sizes="192x192">
<link rel="apple-touch-icon" href="/favicon-192.png">
<link rel="manifest" href="/manifest.json">
```

### manifest.json (Create at Root)
```json
{
  "name": "[INPUT_NAME]",
  "short_name": "[INPUT_NAME]",
  "description": "Best [niche] in [location1] and [location2]",
  "icons": [
    { "src": "/favicon-48.png", "sizes": "48x48", "type": "image/png" },
    { "src": "/favicon-192.png", "sizes": "192x192", "type": "image/png" }
  ],
  "start_url": "/",
  "display": "browser",
  "theme_color": "[INPUT_COLOR2]",
  "background_color": "[INPUT_COLOR2]"
}
```

### PowerShell to Generate Proper Favicon Sizes from Original
```powershell
Add-Type -AssemblyName System.Drawing
$utf8 = New-Object System.Text.UTF8Encoding($false)
$src = [System.Drawing.Image]::FromFile(".\original-logo.png")

foreach ($size in @(48, 192)) {
    $bmp = New-Object System.Drawing.Bitmap($size, $size)
    $g = [System.Drawing.Graphics]::FromImage($bmp)

    $g.DrawImage($src, 0, 0, $size, $size)
    $g.Dispose()

    $bmp.Dispose()
}
$src.Dispose()
Write-Host "Favicons created."
```

## STEP 9 — H1 RULE (Most Commonly Broken SEO Element)

**The primary keyword MUST come first. Brand name comes after.**

```
WRONG: "[Brand Name] - The Best [Niche] in [Location]"
RIGHT: "Best [Niche] in [Location1] and [Location2] - [Brand Name]"
```

Why: Google's algorithm weights the beginning of the H1 most heavily.
If H1 is controlled by a JavaScript translation system (data-i18n), changing the HTML is NOT enough.
You MUST also update the English translation value in the JS translations dictionary.

## STEP 11 — MULTILINGUAL SEO

### 11.1 Use Client-Side JS Dictionary (NOT Google Translate API)
Google Translate API breaks pages and ruins SEO. Use manual translation dictionary.

```javascript
const translations = {
  en: {
    "hero.title": "Best [Niche] in [Location1] and [Location2] - [INPUT_NAME]",
    "hero.subtitle": "English subtitle..."
  },
  hi: {
    "hero.title": "Hindi title...",
    "hero.subtitle": "Hindi subtitle..."
  },
  bn: {
    "hero.title": "Bengali title...",
    "hero.subtitle": "Bengali subtitle..."
  }
};

function setLanguage(lang) {
  localStorage.setItem('siteLang', lang);
  document.querySelectorAll('[data-i18n]').forEach(el => {
    const key = el.getAttribute('data-i18n');
    if (translations[lang] && translations[lang][key]) {
      el.innerHTML = translations[lang][key];
    }
  });
}
document.getElementById('language-select').addEventListener('change', e => setLanguage(e.target.value));
const saved = localStorage.getItem('siteLang') || 'en';
document.getElementById('language-select').value = saved;
setLanguage(saved);
```

### 11.2 CRITICAL RULE — JS Translations Override HTML
When you update visible text in HTML, you MUST ALSO update the translations object.
The JS translation runs on page load and overwrites the HTML content.
If you change the H1 in HTML but forget script.js — the OLD text will appear on screen.

### 11.3 Every i18n Key Must Exist in ALL Languages
Run an audit before launch:
- Extract all `data-i18n="key"` values from HTML
- Confirm every key exists in translations.en, translations.hi, translations.bn
- Missing keys = blank text visible to users

- Hero background: **JPG** (max 300KB, compressed from original)
- Portrait photos: **JPG** (max 200KB)
- Logo with transparency: **PNG** (max 100KB)
- OG/Social images: **JPG only** — PNG is too slow for social preview crawlers

### Alt Text Formula
```
[What is shown in image] + [primary keyword] + [location]

BAD:  alt="Logo"
GOOD: alt="[INPUT_NAME] - Best [Niche] in [Location1] and [Location2]"

BAD:  alt="Service image"
GOOD: alt="[Service] at [Location1] by Best [Niche] in [State]"
```

### OG Image Path Rule
Always use absolute URL with `.jpg` extension:
```html
<meta property="og:image" content="[INPUT_DOMAIN]/images/portrait.jpg">
<!-- NOT: /images/portrait.png — that file may not exist after image optimization -->
```

## STEP 14 — ENCODING & SPECIAL CHARACTERS (Prevents Garbage Text in Google)

### The Most Dangerous Bug: Character Encoding Corruption
When PowerShell processes HTML files with emoji or special Unicode characters,
those characters can get corrupted into garbage like `â˜°` (instead of ☰) or `A_A­A¡` (instead of —).
Google then shows the garbage in search results — destroying click-through rates.

### Safe Icons (Use HTML Entities, Never Raw Unicode in Files)

```
Hamburger menu:  &#9776; or ☰ (verify visually after any script runs)
Star rating:     &#9733; or ★
Location pin:    &#x1F4CD;
Phone:           &#x1F4DE;
WhatsApp:        &#x1F4AC;
Right arrow:     &rarr; or &#8594;
Em-dash:         &mdash; or &#8212;
```

### PowerShell Encoding — ALWAYS Use This Pattern

```powershell
# CORRECT — Read
$c = [System.IO.File]::ReadAllText($path, [System.Text.Encoding]::UTF8)

# CORRECT — Write (UTF-8 without BOM)
$utf8NoBom = New-Object System.Text.UTF8Encoding($false)
[System.IO.File]::WriteAllText($path, $c, $utf8NoBom)

# NEVER USE (corrupts special characters):
# $c = Get-Content $path
# Set-Content $path $c
```

### Post-Script Verification
After any automated script runs on HTML files, always verify:
- Hamburger menu icon still shows (☰ not â˜°)
- Star ratings still show (★ not â˜…)
- Language labels (Hindi/Bengali text) still render correctly
- Meta descriptions have no garbage characters


## KNOWN ISSUES LOG (Lessons from Live Site)

| Issue | Root Cause | Fix |
|---|---|---|
| Favicon shows in tab but not Google Search | Favicon file was 2.5MB — Google refuses to download | Resize to 48px and 192px, max 100KB |
| H1 not updating despite HTML change | data-i18n JS overwrites HTML on load | Must update script.js translations too |
| Hamburger menu icon disappears | PowerShell corrupted UTF-8 characters | Always use File::ReadAllText/WriteAllText |
| Stars not showing in testimonials | Same UTF-8 corruption | Same fix |
| Duplicate LocalBusiness schemas | Multiple SEO scripts added schemas separately | Check before adding: `if ($c -notmatch '"LocalBusiness"')` |
| Meta description shows garbage in Google | Script used Get-Content corrupting em-dashes | Use clean ASCII in all meta descriptions — no special chars |
| OG images broken on social share | File was .png but OG tag said .png — file was converted to .jpg | Always verify OG image paths match actual files on disk |
| index.html missing from sitemap | Sitemap had `/` but not `/index.html` — Google treats them separately | Add both `/` and `/index.html` to sitemap |
| About title same as hero title | JS translations had same value for `about.title` and `hero.title` | Each section needs its own unique translation key value |
